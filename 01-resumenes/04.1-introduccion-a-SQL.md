# Introducción a SQL

Este documento describe los tipos de datos más comunes en SQL y muestra un ejemplo de creación de una base de datos y tablas en SQL Server.

## Tipos de datos

### Numéricos

#### Sin coma
- `INT` — Número entero de tamaño estándar. Se usa para IDs, contadores o valores enteros comunes.
- `INTEGER` — Sinónimo de `INT` en la mayoría de los motores SQL. Mismo uso.
- `SMALLINT` — Entero pequeño. Ahorra espacio cuando los valores son reducidos (por ejemplo, edades).
- `BIGINT` — Entero muy grande. Se usa cuando `INT` no es suficiente, como IDs masivos o contadores grandes.

#### Con coma
- `DECIMAL` — Número exacto con decimales. Ideal para dinero y cálculos precisos.
- `NUMERIC` — Similar a `DECIMAL`. Por ejemplo, `NUMERIC(10,2)` almacena hasta 10 dígitos con 2 decimales.
- `FLOAT` — Número con coma flotante aproximado. Se usa en cálculos científicos donde la precisión exacta no es crítica.
- `REAL` — Similar a `FLOAT` pero con menor precisión.
- `DOUBLE` — Coma flotante de doble precisión. Más exacto que `FLOAT`, pero sigue siendo aproximado.

### Cadena de texto
- `CHAR` — Cadena de longitud fija. Si defines `CHAR(10)`, siempre ocupa 10 caracteres. Útil para códigos fijos.
- `VARCHAR` — Cadena de longitud variable. Ahorra espacio. Es el tipo más usado para texto corto.
- `VARCHARN` — Variante específica de algunos motores. Similar a `VARCHAR` pero con soporte Unicode.
- `TEXT` — Texto largo. Se usa para descripciones, comentarios o contenido extenso.

### Fecha y hora
- `DATE` — Guarda solo fechas. Formato típico: `2026-01-24`.
- `TIME` — Guarda solo horas. Incluye fracciones de segundo, por ejemplo: `07:46:23.785`.
- `DATETIME` — Guarda fecha y hora juntas. No depende de zona horaria.
- `TIMESTAMP` — Guarda fecha y hora basada en tiempo Unix. Puede ajustarse automáticamente a la zona horaria y se usa para registros de creación y actualización.

### Booleano
- `BOOLEAN` — Guarda valores lógicos: `TRUE` o `FALSE`.
- `BOOL` — Alias de `BOOLEAN` en muchos motores SQL.

### Binarios
- `BINARY` — Datos binarios de longitud fija. Útil para hashes o claves.
- `VARBINARY` — Datos binarios de longitud variable. Ahorra espacio frente a `BINARY`.
- `BLOB` — Objetos binarios grandes. Se usa para imágenes, archivos o audio.

### Otros comunes
- `ENUM` — Lista de valores predefinidos. Solo permite uno de ellos, por ejemplo: `estado = 'ACTIVO'`.
- `SET` — Similar a `ENUM`, pero permite múltiples valores al mismo tiempo.
- `JSON` — Almacena datos en formato JSON. Muy útil para estructuras flexibles.
- `UUID` — Identificador único universal. Se usa como alternativa a IDs numéricos.

## Ejemplos de consultas y creación de objetos en SQL Server

A continuación se muestran ejemplos de comandos para explorar un servidor SQL Server, crear una base de datos y definir tablas con claves primarias y foráneas.

```sql
-- Selecciona la base de datos master (base del sistema)
USE master;
GO

-- Muestra todas las bases de datos del servidor
SELECT * FROM sys.databases;
GO

-- Muestra todas las tablas de la base analiticadot
SELECT * FROM analiticadot.sys.tables;
GO

-- Muestra todas las columnas de la base analiticadot
SELECT * FROM analiticadot.sys.columns;
GO

-- Cambia el contexto a la base de datos analiticadot
USE analiticadot;
GO

-- Lista las tablas de la base actual
SELECT * FROM sys.tables;
GO

-- Crea la base de datos curso20262401
CREATE DATABASE curso20262401;
GO

-- Cambia el contexto a la nueva base de datos
USE curso20262401;
GO

-- Creación de la tabla pais
CREATE TABLE pais (
    pais_id INT PRIMARY KEY NOT NULL,
    nombre VARCHAR(64) NOT NULL,
    capital VARCHAR(64) NOT NULL,
    poblacion INT NOT NULL
);
GO

-- Creación de la tabla autor
CREATE TABLE autor (
    autor_id INT PRIMARY KEY NOT NULL,
    nombres VARCHAR(128) NOT NULL,
    apellidos VARCHAR(128) NOT NULL,
    nacimiento DATE NULL,
    pais_id INT NOT NULL,
    REFERENCES pais (pais_id)
);
GO

-- Creación de la tabla obra
CREATE TABLE obra (
    obra_id INT NOT NULL PRIMARY KEY,
    nombre VARCHAR(128) NOT NULL,
    publicacion DATE NULL
);
GO

-- Creación de la tabla escrita
-- Representa la relación muchos a muchos entre obra y autor
CREATE TABLE escrita (
    obra_id INT NOT NULL REFERENCES obra (obra_id),
    autor_id INT NOT NULL REFERENCES autor (autor_id),
    porcentaje NUMERIC(6,2) NOT NULL
);
GO

-- Agrega la clave primaria compuesta a la tabla escrita
ALTER TABLE escrita
    ADD PRIMARY KEY (obra_id, autor_id);
GO
```
