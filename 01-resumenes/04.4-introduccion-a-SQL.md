## SECCIÓN 1. CREACIÓN DE LA BASE DE DATOS Y LA TABLA `Pais`

**Objetivos:**
- Crear una base de datos reproducible para practicar `GROUP BY`.
- Definir la estructura de la tabla `Pais`.
- Preparar el escenario para ejercicios de agregación y agrupamiento.

**Conceptos:**
- `CREATE DATABASE`: crea la base de datos de trabajo.
- `USE`: selecciona la base de datos activa.
- `CREATE TABLE`: define la estructura de una tabla.
- `IDENTITY PRIMARY KEY`: genera automáticamente la clave primaria.

**Errores frecuentes:**
- Olvidar seleccionar la base de datos con `USE`.
- Definir la tabla sin clave primaria.
- No respetar el tipo de dato para `Poblacion`.

### SQL de creación
```sql
CREATE DATABASE DemoSQL;
GO

USE DemoSQL;
GO

CREATE TABLE Pais (
    PaisID       INT IDENTITY PRIMARY KEY,
    Nombre       VARCHAR(100),
    Capital      VARCHAR(100),
    Poblacion    INT,
    Continente   VARCHAR(50),
    Idioma       VARCHAR(50)
);
GO
```

### Resumen de la sección
- Cómo crear una base de ejemplo sencilla y reutilizable.
- Cómo definir una tabla con una clave primaria automática.
- Cómo preparar el esquema necesario para prácticas de SQL.

**Conceptos que deben dominarse:**
- Sintaxis básica de `CREATE DATABASE` y `CREATE TABLE`.
- Uso de `IDENTITY` para claves de tipo entero.
- Importancia de mantener una estructura coherente para el análisis.

## SECCIÓN 3. CONCEPTOS FUNDAMENTALES DE `GROUP BY`

**Objetivos:**
- Comprender el flujo lógico de una consulta con `GROUP BY`.
- Reconocer la diferencia entre `WHERE`, `GROUP BY` y `HAVING`.
- Entender las reglas fundamentales para escribir agregaciones correctas.

**Conceptos:**
- `FROM`: define la fuente de datos.
- `WHERE`: filtra filas antes del agrupamiento.
- `GROUP BY`: agrupa filas por valor de una o varias columnas.
- `HAVING`: filtra grupos ya formados.
- `SELECT`: muestra el resultado final.
- `ORDER BY`: ordena la salida.

**Errores frecuentes:**
- Incluir columnas en `SELECT` sin agregarlas ni agruparlas.
- Intentar usar `HAVING` para filtrar filas antes de agrupar.
- No distinguir entre una condición sobre filas y una condición sobre grupos.

### SQL de flujo lógico
```sql
-- Flujo lógico recomendado en consultas con agregación.
SELECT Continente, SUM(Poblacion) AS PoblacionTotal
FROM Pais
GROUP BY Continente
ORDER BY Continente;
GO
```

### Resumen de la sección
- El orden correcto de evaluación de una consulta con agregación.
- Las reglas esenciales para usar `GROUP BY` sin errores.
- La diferencia entre `WHERE` y `HAVING`.

**Conceptos que deben dominarse:**
- El flujo lógico de evaluación.
- Uso de columnas agregadas y columnas de agrupación.
- Importancia de `HAVING` en consultas resumen.

## SECCIÓN 4. CONSULTAS DE AGREGACIÓN

**Objetivos:**
- Calcular poblaciones totales por continente e idioma.
- Identificar el valor de `SUM` como operación de resumen.
- Reconocer la utilidad de las funciones agregadas en reportes.

**Conceptos:**
- `SUM`: calcula la suma acumulada.
- `GROUP BY`: agrupa los registros antes de agregar.
- El resultado final cambia según la columna elegida para agrupar.

**Errores frecuentes:**
- Olvidar incluir la columna de agrupación en `GROUP BY`.
- Usar `SUM` sin tener claridad del nivel de detalle requerido.
- Confundir la agrupación por `Idioma` y por `Continente`.

### SQL de agregación
```sql
-- Población total por continente.
SELECT Continente, SUM(Poblacion) AS PoblacionTotal
FROM Pais
GROUP BY Continente;
GO

-- Población total por idioma.
SELECT Idioma, SUM(Poblacion) AS PoblacionTotal
FROM Pais
GROUP BY Idioma;
GO
```

### Resumen de la sección
- Cómo resumir datos con una sola función agregada.
- Cómo el resultado cambia dependiendo de la clave de agrupación.
- Cómo construir reportes simples con `GROUP BY`.

**Conceptos que deben dominarse:**
- Uso de `SUM` sobre columnas numéricas.
- Vínculo entre `GROUP BY` y la salida esperada.
- Lectura de resultados de resumen.

## SECCIÓN 5. CONTEOS

**Objetivos:**
- Aplicar `COUNT` para contar filas en grupos.
- Usar `COUNT DISTINCT` para contar categorías únicas.
- Explorar agrupaciones con expresiones derivadas.

**Conceptos:**
- `COUNT(*)`: cuenta filas completas.
- `COUNT(DISTINCT ...)`: cuenta valores únicos en una columna.
- `LEFT(...)`: extrae la inicial de un texto.

**Errores frecuentes:**
- Pensar que `COUNT` siempre cuenta valores distintos.
- No usar `DISTINCT` cuando se necesita contar categorías únicas.
- Olvidar que `LEFT(Capital,1)` debe aparecer también en `GROUP BY`.

### SQL de conteos
```sql
-- Conteo de países por continente.
SELECT Continente, COUNT(*) AS TotalPaises
FROM Pais
GROUP BY Continente;
GO

-- Conteo de países por idioma.
SELECT Idioma, COUNT(*) AS TotalPaises
FROM Pais
GROUP BY Idioma;
GO

-- Conteo de capitales por inicial.
SELECT LEFT(Capital,1) AS Inicial, COUNT(*) AS TotalCapitales
FROM Pais
WHERE Capital LIKE 'A%'
GROUP BY LEFT(Capital,1);
GO
```

### Resumen de la sección
- Cómo contar registros dentro de cada grupo.
- Cómo contar valores distintos cuando hace falta.
- Cómo usar expresiones simples para agrupar por patrones.

**Conceptos que deben dominarse:**
- Diferencia entre `COUNT(*)` y `COUNT(DISTINCT ...)`.
- Uso de `LEFT` dentro de agregaciones.
- Aplicación práctica de `WHERE` previo al `GROUP BY`.

## SECCIÓN 6. AGRUPAMIENTOS ADICIONALES

**Objetivos:**
- Clasificar datos mediante `CASE` dentro de un `GROUP BY`.
- Calcular promedios, máximos y mínimos por grupo.
- Explorar idiomas distintos por continente y filtros posteriores con `HAVING`.

**Conceptos:**
- `CASE`: permite crear rangos o categorías.
- `AVG`: calcula el promedio por grupo.
- `MAX` y `MIN`: obtienen los valores extremos.
- `COUNT(DISTINCT ...)`: cuenta categorías distintas.

**Errores frecuentes:**
- Repetir la expresión `CASE` en `SELECT` y `GROUP BY` sin tener un criterio claro.
- Usar `AVG` sin controlar el nivel de detalle de los datos.
- Confundir el resultado de `HAVING` con el de `WHERE`.

### SQL de agrupaciones adicionales
```sql
-- Rangos de población con CASE.
SELECT 
    CASE 
        WHEN Poblacion < 5000000 THEN 'Pequeno'
        WHEN Poblacion BETWEEN 5000000 AND 20000000 THEN 'Mediano'
        ELSE 'Grande'
    END AS RangoPoblacion,
    COUNT(*) AS TotalPaises
FROM Pais
GROUP BY 
    CASE 
        WHEN Poblacion < 5000000 THEN 'Pequeno'
        WHEN Poblacion BETWEEN 5000000 AND 20000000 THEN 'Mediano'
        ELSE 'Grande'
    END;
GO

-- Promedio de población por continente.
SELECT Continente, AVG(Poblacion) AS PromedioPoblacion
FROM Pais
GROUP BY Continente;
GO

-- Máximo y mínimo por idioma.
SELECT Idioma,
       MAX(Poblacion) AS MaxPoblacion,
       MIN(Poblacion) AS MinPoblacion
FROM Pais
GROUP BY Idioma;
GO

-- Idiomas distintos por continente.
SELECT Continente, COUNT(DISTINCT Idioma) AS IdiomasDistintos
FROM Pais
GROUP BY Continente;
GO

-- Capitales agrupadas por inicial.
SELECT LEFT(Capital,1) AS Inicial, COUNT(*) AS Total
FROM Pais
GROUP BY LEFT(Capital,1)
ORDER BY Inicial;
GO

-- Uso de HAVING.
SELECT Continente, COUNT(*) AS TotalPaises
FROM Pais
GROUP BY Continente
HAVING COUNT(*) > 5;
GO
```

### Resumen de la sección
- Cómo construir categorías con `CASE` para reportes más claros.
- Cómo resumir datos con `AVG`, `MAX` y `MIN`.
- Cómo `HAVING` refina la salida final luego del agrupamiento.

**Conceptos que deben dominarse:**
- Uso de `CASE` para crear rangos.
- Diferencia de resultado entre `GROUP BY` y `HAVING`.
- Aplicación práctica de `COUNT(DISTINCT ...)`.
