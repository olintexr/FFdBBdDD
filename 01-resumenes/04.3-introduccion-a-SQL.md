**Conceptos:**
- `TRUNCATE TABLE`: elimina todos los registros de una tabla, pero mantiene la estructura.
- `DELETE FROM`: también borra filas, pero puede ser más lento y más flexible.
- `INSERT INTO`: agrega datos para poder ejecutar consultas posteriores.

- Insertar productos con códigos repetidos.

## SECCIÓN 2. JOIN Y CÁLCULO DE MONTOS

**Objetivos:**
- Relacionar tablas con `INNER JOIN`.
- Calcular el monto por renglón usando cantidad por precio.
- Ordenar el resultado para leerlo mejor.

**Conceptos:**
- `INNER JOIN`: une tablas solo cuando hay coincidencias.
- `CAST(...) AS numeric(...)`: convierte un valor numérico al tipo deseado.
- `ORDER BY`: define el orden final de la salida.

**Errores frecuentes:**
- No usar la condición correcta en `ON`.
- Olvidar alias de tablas cuando hay columnas con el mismo nombre.
- Confundir el orden de ejecución de `JOIN` y `ORDER BY`.

### SQL de joins y cálculos
```sql
-- Esta consulta muestra el cliente, la factura, el producto y el monto de cada renglón.
-- El cálculo del monto se hace con cantidad * precio.
SELECT
    pr.Nombre,
    f.NumeroFactura,
    r.Producto,
    r.cantidad,
    p.precio,
    CAST(r.cantidad * p.precio AS NUMERIC(10,2)) AS monto
FROM renglon AS r
INNER JOIN producto AS p
    ON r.Producto = p.Producto
INNER JOIN factura AS f
    ON f.NumeroFactura = r.Factura
INNER JOIN Persona AS pr
    ON pr.Cedula = f.Cedula
ORDER BY pr.nombre, f.NumeroFactura, r.producto;
GO
```

### Resumen de la sección
- A combinar varias tablas con joins.
- A calcular montos con expresiones aritméticas.
- A ordenar los resultados para análisis visual.

**Conceptos que deben dominarse:**
- Relación entre tablas mediante claves.
- Uso correcto de alias.
- Conversión de tipos con `CAST`.

## SECCIÓN 3. CTE (EXPRESIÓN DE TABLA COMÚN)

**Objetivos:**
- Entender cómo una CTE ayuda a organizar consultas complejas.
- Reutilizar una subconsulta como si fuera una tabla temporal.
- Verificar el resultado antes de aplicar agregaciones.

**Conceptos:**
- `WITH ... AS (...)`: define una consulta temporal llamada CTE.
- La CTE puede usarse luego como si fuera una tabla.
- Sirve para leer y depurar consultas paso a paso.

**Errores frecuentes:**
- Intentar usar la CTE fuera del bloque donde fue definida.
- Olvidar que la CTE no sustituye el `SELECT` principal.
- Mezclar demasiadas operaciones en una sola consulta.

### SQL con CTE
```sql
-- Esta CTE guarda el resultado de la consulta de joins para poder reutilizarlo.
-- Luego se consulta la CTE como si fuera una tabla normal.
;WITH cte_factura AS (
    SELECT
        pr.Nombre,
        f.NumeroFactura,
        r.Producto,
        r.cantidad,
        p.precio,
        CAST(r.cantidad * p.precio AS NUMERIC(10,2)) AS monto
    FROM renglon AS r
    INNER JOIN producto AS p
        ON r.Producto = p.Producto
    INNER JOIN factura AS f
        ON f.NumeroFactura = r.Factura
    INNER JOIN Persona AS pr
        ON pr.Cedula = f.Cedula
)
SELECT *
FROM cte_factura
ORDER BY nombre, NumeroFactura, producto;
GO
```

### Resumen de la sección
- Cómo definir una CTE.
- Cómo separar la lógica compleja en pasos.
- Cómo revisar resultados intermedios antes de agregarlos.

**Conceptos que deben dominarse:**
- Ventajas de una CTE para lectura y mantenimiento.
- Cómo la CTE mejora la claridad de consultas largas.
- Uso de `ORDER BY` sobre el resultado final.

## SECCIÓN 4. FUNCIONES DE AGREGACIÓN

**Objetivos:**
- Aprender a resumir datos con `SUM`, `AVG`, `MAX`, `MIN` y `COUNT`.
- Comprender que las funciones agregadas trabajan sobre grupos de filas.
- Ver cómo se puede calcular el total de una consulta base.

**Conceptos:**
- `SUM`: suma valores.
- `AVG`: calcula el promedio.
- `MAX` / `MIN`: obtienen el mayor y el menor valor.
- `COUNT`: cuenta filas o valores.

**Errores frecuentes:**
- Usar funciones agregadas sin pensar en el nivel de detalle de la consulta.
- Confundir contar filas con contar valores no nulos.
- Esperar que `SUM` funcione como si fuera una columna normal.

### SQL con agregaciones
```sql
-- Este ejemplo suma todo lo que aparece en la CTE.
-- El resultado es un único registro con el total general.
;WITH cte_factura AS (
    SELECT
        pr.Nombre,
        f.NumeroFactura,
        r.Producto,
        r.cantidad,
        p.precio,
        CAST(r.cantidad * p.precio AS NUMERIC(10,2)) AS monto
    FROM renglon AS r
    INNER JOIN producto AS p
        ON r.Producto = p.Producto
    INNER JOIN factura AS f
        ON f.NumeroFactura = r.Factura
    INNER JOIN Persona AS pr
        ON pr.Cedula = f.Cedula
)
SELECT
    SUM(monto) AS total,
    SUM(cantidad) AS cuantos
FROM cte_factura;
GO

-- Aquí se muestran varias funciones agregadas sobre la misma CTE.
-- Cada una resume una parte distinta del conjunto de datos.
;WITH cte_factura AS (
    SELECT
        pr.Nombre,
        f.NumeroFactura,
        r.Producto,
        r.cantidad,
        p.precio,
        CAST(r.cantidad * p.precio AS NUMERIC(10,2)) AS monto
    FROM renglon AS r
    INNER JOIN producto AS p
        ON r.Producto = p.Producto
    INNER JOIN factura AS f
        ON f.NumeroFactura = r.Factura
    INNER JOIN Persona AS pr
        ON pr.Cedula = f.Cedula
)
SELECT
    SUM(monto) AS total,
    SUM(cantidad) AS cuantos,
    AVG(monto) AS avm,
    AVG(cantidad) AS avgc,
    MAX(monto) AS mxm,
    MAX(cantidad) AS mxc,
    MIN(monto) AS mnm,
    MIN(cantidad) AS mnc,
    COUNT(*) AS cnt1,
    SUM(1) AS cnt2
FROM cte_factura;
GO
```

### Resumen de la sección
- Cómo resumir grandes conjuntos con funciones agregadas.
- Qué significa cada función (`SUM`, `AVG`, `MAX`, `MIN`, `COUNT`).
- Cómo los resultados cambian según el nivel de detalle de la consulta.

**Conceptos que deben dominarse:**
- Diferencia entre una fila individual y un resumen global.
- Uso de `COUNT(*)` vs `COUNT(columna)`.
- Importancia de la CTE como base para agregaciones.

## SECCIÓN 5. GROUP BY Y HAVING

**Objetivos:**
- Agrupar filas con `GROUP BY`.
- Aplicar filtros a los grupos con `HAVING`.
- Diferenciar claramente entre `WHERE` y `HAVING`.

**Conceptos:**
- `GROUP BY`: crea grupos de filas con el mismo valor en una o más columnas.
- `WHERE`: filtra filas antes de agrupar.
- `HAVING`: filtra grupos después de agrupar.

**Errores frecuentes:**
- Usar `WHERE` con funciones agregadas.
- Olvidar incluir en `GROUP BY` las columnas que se muestran sin agregación.
- Pensar que `HAVING` puede reemplazar a `WHERE` en todo caso.

### SQL de agrupación
```sql
-- Este ejemplo agrupa por nombre del cliente y muestra los totales por persona.
;WITH cte_factura AS (
    SELECT
        pr.Nombre,
        f.NumeroFactura,
        r.Producto,
        r.cantidad,
        p.precio,
        CAST(r.cantidad * p.precio AS NUMERIC(10,2)) AS monto
    FROM renglon AS r
    INNER JOIN producto AS p
        ON r.Producto = p.Producto
    INNER JOIN factura AS f
        ON f.NumeroFactura = r.Factura
    INNER JOIN Persona AS pr
        ON pr.Cedula = f.Cedula
)
SELECT
    nombre,
    SUM(monto) AS total,
    SUM(cantidad) AS cuantos,
    AVG(monto) AS avm,
    AVG(cantidad) AS avgc,
    MAX(monto) AS mxm,
    MAX(cantidad) AS mxc,
    MIN(monto) AS mnm,
    MIN(cantidad) AS mnc,
    COUNT(*) AS cnt1,
    SUM(1) AS cnt2
FROM cte_factura
GROUP BY nombre;
GO

-- Este ejemplo filtra primero por cliente y luego agrupa.
-- Como `WHERE` actúa antes del agrupado, se eliminan filas no deseadas.
;WITH cte_factura AS (
    SELECT
        pr.Nombre,
        f.NumeroFactura,
        r.Producto,
        r.cantidad,
        p.precio,
        CAST(r.cantidad * p.precio AS NUMERIC(10,2)) AS monto
    FROM renglon AS r
    INNER JOIN producto AS p
        ON r.Producto = p.Producto
    INNER JOIN factura AS f
        ON f.NumeroFactura = r.Factura
    INNER JOIN Persona AS pr
        ON pr.Cedula = f.Cedula
)
SELECT
    nombre,
    SUM(monto) AS total,
    SUM(cantidad) AS cuantos,
    AVG(monto) AS avm,
    AVG(cantidad) AS avgc,
    MAX(monto) AS mxm,
    MAX(cantidad) AS mxc,
    MIN(monto) AS mnm,
    MIN(cantidad) AS mnc,
    COUNT(*) AS cnt1,
    SUM(1) AS cnt2
FROM cte_factura
WHERE nombre = 'Águeda'
GROUP BY nombre;
GO

-- Este ejemplo usa `HAVING` para filtrar grupos ya formados.
-- Aquí se mantiene solo el grupo cuyo total de cantidad sea mayor o igual a 10.
;WITH cte_factura AS (
    SELECT
        pr.Nombre,
        f.NumeroFactura,
        r.Producto,
        r.cantidad,
        p.precio,
        CAST(r.cantidad * p.precio AS NUMERIC(10,2)) AS monto
    FROM renglon AS r
    INNER JOIN producto AS p
        ON r.Producto = p.Producto
    INNER JOIN factura AS f
        ON f.NumeroFactura = r.Factura
    INNER JOIN Persona AS pr
        ON pr.Cedula = f.Cedula
)
SELECT
    producto,
    SUM(monto) AS total,
    SUM(cantidad) AS cuantos,
    AVG(monto) AS avm,
    AVG(cantidad) AS avgc,
    MAX(monto) AS mxm,
    MAX(cantidad) AS mxc,
    MIN(monto) AS mnm,
    MIN(cantidad) AS mnc,
    COUNT(*) AS cnt1,
    SUM(1) AS cnt2
FROM cte_factura
GROUP BY producto
HAVING SUM(cantidad) >= 10;
GO
```

### Resumen de la sección
- Cómo agrupar resultados por una columna.
- Cómo `WHERE` y `HAVING` sirven para propósitos distintos.
- Cómo obtener resúmenes por cliente o por producto.

**Conceptos que deben dominarse:**
- La diferencia entre filtrar filas y filtrar grupos.
- La relación entre `GROUP BY` y las funciones agregadas.
- El uso correcto de `HAVING` para agregados.

## SECCIÓN 6. ORDEN DE EVALUACIÓN DE UNA CONSULTA

**Objetivos:**
- Comprender el orden lógico en que SQL procesa una consulta.
- Identificar el rol de cada cláusula.
- Evitar errores comunes al escribir consultas complejas.

**Conceptos:**
- `FROM`: define las tablas base.
- `WHERE`: filtra filas.
- `GROUP BY`: arma grupos.
- `HAVING`: filtra grupos.
- `SELECT`: calcula columnas y alias.
- `ORDER BY`: ordena el resultado final.

**Errores frecuentes:**
- Pensar que `SELECT` se ejecuta antes de `WHERE`.
- Esperar que `HAVING` pueda reemplazar completamente a `WHERE`.
- Usar alias de `SELECT` en `WHERE` cuando eso no aplica.

### SQL del orden lógico
```sql
-- Este bloque sirve como referencia visual para recordar el orden correcto.
-- En SQL, la lógica suele ser:
-- 1. FROM
-- 2. WHERE
-- 3. GROUP BY
-- 4. HAVING
-- 5. SELECT
-- 6. ORDER BY

/*
   +------------------------------------------------------+
   | 1. FROM                                              |
   |    - Se eligen las tablas                            |
   |    - Se aplican los JOIN                             |
   +------------------------------------------------------+

   +------------------------------------------------------+
   | 2. WHERE                                             |
   |    - Se filtran filas                                |
   |    - No se permiten agregados aquí                   |
   +------------------------------------------------------+

   +------------------------------------------------------+
   | 3. GROUP BY                                          |
   |    - Se forman grupos                                |
   |    - Cada grupo será una fila lógica                 |
   +------------------------------------------------------+

   +------------------------------------------------------+
   | 4. HAVING                                            |
   |    - Se filtran grupos                               |
   |    - Aquí sí se permiten SUM, AVG, COUNT, etc.       |
   +------------------------------------------------------+

   +------------------------------------------------------+
   | 5. SELECT                                            |
   |    - Se calculan columnas                            |
   |    - Se aplican funciones de agregado                |
   |    - Se evalúan expresiones                          |
   +------------------------------------------------------+

   +------------------------------------------------------+
   | 6. ORDER BY                                          |
   |    - Se ordenan las filas finales                    |
   |    - Puede usar alias del SELECT                     |
   +------------------------------------------------------+
*/
```

### Resumen de la sección
- Cómo recordar el orden lógico de una consulta SQL.
- Qué hace cada cláusula en el proceso completo.
- Cómo evitar errores al escribir consultas más complejas.

**Conceptos que deben dominarse:**
- Estructura general de una consulta.
- Diferencia entre filas y grupos.
- Uso correcto de agregados, filtros y ordenamiento.
